# 如何在專案中使用 Obsidian MCP Monitor

## 重要概念

MCP Server 是**獨立運行的服務**，不是像 npm 套件那樣安裝到專案中。它通過**配置文件**連接到 Claude。

## 📍 三種使用方式

### 方式 1：Claude Desktop 全域配置 ✅（已完成）

**配置文件位置**：
```
C:\Users\whoam\AppData\Roaming\Claude\claude_desktop_config.json
```

**特點**：
- ✅ 已經配置完成
- 在 Claude Desktop 的所有對話中都可使用
- 不需要額外設定

**配置內容**：
```json
{
  "mcpServers": {
    "obsidian-monitor": {
      "command": "node",
      "args": [
        "C:\\Users\\SyncthingServiceAcct\\Obs20240105\\Obs20240105\\06. Principles\\06. 04. Vibe Coding\\Steering Docs\\obsidian-mcp-monitor\\dist\\index.js"
      ]
    }
  }
}
```

---

### 方式 2：Claude Code 全域配置 ✅（已完成）

Claude Code（CLI）會**自動讀取**與 Claude Desktop 相同的配置文件。

**特點**：
- ✅ 已經配置完成（與 Claude Desktop 共用）
- 在任何目錄執行 `claude` 命令都可使用
- 不需要額外設定

---

### 方式 3：Claude Code 專案級配置 ✅（已完成）

**配置文件位置**：
```
<專案根目錄>/.claude/.mcp.json
```

**本專案配置**：
```
C:\Users\SyncthingServiceAcct\Obs20240105\Obs20240105\06. Principles\06. 04. Vibe Coding\Steering Docs\.claude\.mcp.json
```

**特點**：
- ✅ 已加入到本專案的 `.claude/.mcp.json`
- 只在此專案目錄下執行 `claude` 時生效
- 可以覆蓋全域配置（如果有衝突）

## 🔄 如何在其他專案使用

### 選項 A：使用全域配置（推薦）

**什麼都不用做！** 因為全域配置已經完成，在任何專案中都可以直接使用。

```bash
cd /path/to/your/other/project
claude
# 在對話中直接使用 obsidian_* 工具
```

---

### 選項 B：專案級配置

如果你想在特定專案加入配置（例如要提交到 git 讓團隊成員也能用）：

1. **在該專案根目錄建立配置文件**：

```bash
mkdir -p .claude
```

2. **建立 `.claude/.mcp.json`**：

```json
{
  "mcpServers": {
    "obsidian-monitor": {
      "command": "node",
      "args": [
        "C:\\Users\\SyncthingServiceAcct\\Obs20240105\\Obs20240105\\06. Principles\\06. 04. Vibe Coding\\Steering Docs\\obsidian-mcp-monitor\\dist\\index.js"
      ]
    }
  }
}
```

3. **（可選）加入 `.gitignore`**：

如果路徑包含個人資訊，可以不要提交：
```gitignore
.claude/.mcp.json
```

然後建立 `.claude/.mcp.json.example` 作為範本。

## 📦 是否需要複製 obsidian-mcp-monitor 資料夾？

### ❌ 不需要！

理由：
1. MCP Server 是**全域服務**，不是專案依賴
2. 配置文件指向**絕對路徑**
3. 只要路徑正確，從任何地方都可以使用

### ✅ 什麼時候需要複製？

只有在以下情況：
- 你想要修改 MCP server 的程式碼
- 你想要建立不同版本的配置
- 你想要發布為獨立專案

## 🔧 路徑配置選項

### 絕對路徑（目前使用）

```json
"args": [
  "C:\\Users\\SyncthingServiceAcct\\Obs20240105\\Obs20240105\\06. Principles\\06. 04. Vibe Coding\\Steering Docs\\obsidian-mcp-monitor\\dist\\index.js"

```

**優點**：明確，不會出錯
**缺點**：不可移植，每台機器都要改

### 相對路徑（進階）

如果你的 MCP server 在專案內：
```json
"args": [
  "${workspaceFolder}/obsidian-mcp-monitor/dist/index.js"
]
```

**注意**：僅在支援 `${workspaceFolder}` 變數的環境中有效。
